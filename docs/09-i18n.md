# 09 – Internationalization (FR / EN / AR)

## 1. Setup
- Library: **next-intl** (App Router). Routes `src/app/[locale]/...`, locales `['fr','en','ar']`, default `fr`, `localePrefix: 'always'`.
- Middleware: detect the locale from the `NEXT_LOCALE` cookie → `Accept-Language` → `fr`. The switcher sets the cookie and keeps the same path and query.
- Messages: `messages/{fr,en,ar}.json`, namespaced by area (`common`, `nav`, `home`, `catalog`, `fabric`, `match`, `showroom`, `account`, `admin`, `emails`, `pdf`, `errors`, `feel`, `legal`). Keys in English camelCase, e.g. `match.steps.style.question`.
- **French is the source language.** Every key must exist in all 3 files; CI runs `scripts/check-i18n.ts` (fails on missing or extra keys, and on ICU syntax errors).
- The admin back-office is translated too (staff may prefer French or Arabic).

## 2. RTL (Arabic)
- `<html lang={locale} dir={locale==='ar' ? 'rtl' : 'ltr'}>`.
- Tailwind: **only logical utilities** (`ms-*`, `me-*`, `ps-*`, `pe-*`, `start-*`, `end-*`, `text-start`, `rounded-s-*`). ESLint rule (custom or `eslint-plugin-tailwindcss` with a forbidden-classes list) forbids `ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`.
- Directional icons (arrows, chevrons) flip with `rtl:-scale-x-100`. The progress bar and wizard steps follow the reading direction.
- 3D scenes and the cloth canvas are not mirrored; their HTML overlays are.
- Fonts: Arabic uses **IBM Plex Sans Arabic** (body + headings), loaded via `next/font` only for `ar`.

## 3. Formatting
- Numbers and currency: `Intl.NumberFormat(locale, { numberingSystem: 'latn' })` → Western digits in every locale (consistent with prices, SKUs, GSM).
- Dates: `Intl.DateTimeFormat(locale, { dateStyle: 'medium' })`, timezone from `app_settings.timezone` (default `Europe/Paris` until the country is confirmed; configurable in admin settings).
- Units are always metric: m, cm, GSM.

## 4. Database content
- Translatable fields are `i18n` jsonb (`04-database.md`). Read with the helper `t(field, locale)` → `field[locale] ?? field.fr`.
- Admin form: tabs FR / EN / AR per translatable field; "Auto-translate missing" button.
- On save, missing EN/AR fields are enqueued to `q_translate` → Claude (`claude-sonnet-5-5`, prompt `TRANSLATE_PROMPT_V1`: "Translate this textile catalog content from French to {target}. Keep technical terms accurate (GSM, jersey, piqué...). Keep brand names. Return only the translation.") → written back and flagged in `fabrics.machine_translated`. The admin sees a "machine translated" badge until they edit the field manually.

## 5. AI in each locale
- Match sessions store `locale`; explanations are generated in that locale.
- Briefs may be written in any of the 3 languages regardless of the UI locale.

## 6. Emails & PDFs
Rendered in the recipient's `profiles.preferred_locale` (staff emails in French by default, setting `staff_locale`). Arabic templates use `dir="rtl"`.

## 7. SEO
`hreflang` alternates for all 3 locales + `x-default` (→ fr) on every public page; localized `<title>` and meta description; localized slugs are **not** used (same slug in all locales).
