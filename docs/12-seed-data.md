## 3. Fabrics (80)
Distribution by category (the generator must hit these counts):
| Category | Count | Typical structures | GSM range |
|---|---|---|---|

| natural-fibers | 10 | plain, twill, satin (linen, silk, organic cotton, wool) | 80–260 |

| upholstery | 8 | canvas, velvet, jacquard (poly, cotton, linen) | 280–600 |
| linings | 4 | plain, twill (viscose, polyester) | 60–100 |

Rules:
- Each fabric gets realistic name (FR + EN + AR), SKU `SAT-{CAT2}-{0001}`, composition summing to 100, width 140–160 (upholstery 280 allowed), stretch consistent with elastane, uses and seasons consistent with category, MOQ 1–50 m, base price 3–45 €/m consistent with fiber/weight, 3 price tiers (MOQ, 100 m: −8%, 500 m: −15%), feel scores left null (estimated by `feel.ts`).
- **Must include** these golden fabrics (used by tests):
  1. `cotton-elastane-pique` – Cotton/Elastane Piqué, 92% cotton / 8% elastane, 240 GSM, 150 cm, knit, pique, two_way, uses activewear/polos, SS (the video's match).
  2. `breathable-poly-mesh` – 100% polyester mesh, 140 GSM, activewear.
  3. `organic-cotton-jersey-180` – 100% organic cotton jersey 180 GSM.
  4. `stretch-denim-12oz` – 98/2 cotton/elastane denim 400 GSM.
  5. `linen-plain-160` – 100% linen plain weave 160 GSM.
  6. `silk-satin-90` – 100% silk satin 90 GSM.
  7. `wool-gabardine-260` – 100% wool gabardine 260 GSM.
  8. `velvet-upholstery-480` – polyester velvet 480 GSM.
  (plus 7 more defined in `tests/match/golden.json` alongside their briefs)
- 10 fabrics `is_featured`.
- Optional: the generator may use Claude once offline to draft names/descriptions, but the **output is committed** as static TS data so seeding is deterministic and free.

## 4. Colors & stock
- 3–8 colors per fabric (total ~400), named realistically (FR/EN/AR), hex values coherent with the fabric type (e.g. denim blues, linen naturals).
- Stock: 1–4 lots per color, 20–800 m each; ~10% of colors out of stock (0 lots), ~10% low stock (< 50 m), assigned to the matching department.
- A handful of reservations, quotes in every status, 6 orders in different statuses with cutting jobs and deliveries, 4 sample requests, so dashboards are populated.

## 5. Placeholder images & textures (`scripts/generate-textures.ts`)
No photos exist, so generate procedural images per color with `sharp` + a small noise library (deterministic seed = color id):
| Structure family | Pattern |
|---|---|
| jersey, interlock, rib | knit loops (V stitches in columns), rib = wider wales |
| pique | small honeycomb cells |
| mesh | regular hole grid |
| plain, poplin, oxford, canvas | over-under weave grid (oxford = 2-yarn basket) |
| twill, denim, gabardine | diagonal twill lines (denim: indigo warp + white weft) |
| satin | smooth with long floats + soft gradient sheen |
| velvet, fleece | fine noise + soft shading |
| chiffon, tulle | transparent fine grid on light background |
| crepe | fine crinkle noise |
| jacquard | repeating geometric motif |
Outputs per color: `photo.webp` (1200×900, with simulated lighting and a slight fold shading, used as the catalog image), `flat_swatch.webp` (1024², tileable), and P3-ready `albedo/normal/roughness` (1024², tileable, `repeat_cm = 10`). Uploaded to the buckets at the normal paths so the app code doesn't know they are fake.
A small "Sample image" watermark is **not** added (it would pollute textures); instead `fabric_images.alt` says "Illustration".

## 6. Replacing seed with real data
- Admin forms (one fabric at a time).
- **CSV import** in `/admin/fabrics` (P1): template download; columns = fabric fields + `colors` as `code:name_fr:hex|...`; dry-run preview with validation errors per row; upsert by SKU. Photos added afterwards via the admin form (bulk upload matching file names `{SKU}_{COLORCODE}_{n}.jpg`).
- A "Purge demo data" admin action deletes everything flagged `is_demo = true` (add `is_demo boolean default false` to fabrics, clients, quotes, orders, samples; the seed sets it to true).
